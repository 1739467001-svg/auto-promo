## 一、背景与目标

**内容定位**：转载在「每日英语听力」等 App 上刷到的**精品外语视频**，配上自制的**中英双语字幕**，做成英语学习素材，分发到抖音、小红书、视频号、B 站等平台，做引流与知识分享。

**痛点与策略**（来自前期分析）：
- 这类内容本质是"他人视频 + 自制字幕"的**字幕二创**，绝大多数平台的"按播放量给钱"激励都要求原创声明，转载身份拿不到。
- 所以真正的价值在**涨粉引流**（抖音/小红书/视频号）+ 后续接广/带货，而非平台激励。
- 转载内容**如实标注**（B 站等如实标"转载"），不冒充原创骗激励。

**工作流要解决的重复劳动**：
1. 同一条视频，要为不同平台写**不同口吻**的文案/标题。
2. 不同平台偏好**不同比例、不同风格**的封面（横版 16:9 / 通用 4:3 / 竖版 3:4）。
3. 手动逐个平台上传费时。

**目标**：一条命令（或一句指令），把上面三件事自动化。

## 二、核心设计原则

| 原则 | 落地方式 |
|---|---|
| **命令驱动，不监听文件夹** | 用户主动发指令（要发哪些平台、文案来源链接），而非后台盯文件夹。简单、可控。 |
| **平台个性化集中管理** | 所有"平台差异"（封面风格、文案口吻、是否标转载、标题字数）收敛到**一个文件** `platforms.py`，作为单一事实来源。 |
| **产出与发布解耦** | 中间用 `PublishPackage`（待发布包）连接两阶段。可以只产出、不发布。 |
| **声明式优先** | 各平台上传流程抽象成"候选选择器规格"，用同一个执行器驱动；平台改版多半只改选择器、不动逻辑。 |
| **安全默认** | 自动发布默认**关闭**，只把内容填好停在"发布"按钮前，由人确认。 |
| **优雅降级** | 抓链接失败、抽帧失败都不中断流程，退化到兜底方案继续。 |
| **依赖可选** | 只用"手写文案 + 手动上传"时，连 `anthropic`、`playwright` 都不用装（惰性导入 + 最小依赖）。 |

## 三、整体架构与数据流

```
                ┌──────────────┐
  input/ 视频 ──▶│              │
  文案来源链接 ──▶│   产出阶段    │── content.md / content.json
  目标平台 ──────▶│  (pipeline)  │── covers/  (各平台专属 + 三张通用)
                └──────┬───────┘
                       │  PublishPackage[]（视频+文案+该平台封面+是否标转载）
                       ▼
                ┌──────────────┐
                │   发布阶段     │── Playwright 复用已登录浏览器
                │  (publish/)  │   填好内容（默认停在发布按钮前）
                └──────────────┘
```

**产出阶段五步**（`pipeline.produce`）：

```
① 识别视频   find_video()      → input/ 里最新的视频（或 --video 指定）
② 拿文案     两条路：
              A) --content：读我写好的 JSON（跳过抓链接 + API，离线）
              B) 默认：fetch_source(link) 抓网页 → generate() 调 Claude 写
③ 出封面     build_covers()    → 抽一次帧，渲染：每平台专属封面 + 三张通用封面
④ 落地产物   _write_outputs()  → content.md（照着发清单）+ content.json
⑤ 组装       PublishPackage[]  → 每个平台一个待发布包，传给发布阶段
```

**数据模型**（`models.py`）：

- `VideoAsset`：识别到的视频（路径、时长）
- `SourceMaterial`：从链接抓回的标题/正文（含 `fetched_ok` 标记）
- `PlatformContent`：单平台成品文案（标题/正文/话题标签）
- `Cover`：一张封面（路径/比例/风格/所属平台）
- `PublishPackage`：待发布包 = 视频 + 文案 + 该平台封面 + 是否标转载
- `PublishResult`：发布结果（成功？是否真的点了发布？）

## 四、两种用法

| 用法 | 文案谁写 | 需要 API Key | 需要浏览器自动化 | 适用 |
|---|---|---|---|---|
| **A. 在 Claude Code App 里用（推荐）** | App 里的 Claude 直接写 | ❌ | ❌ 手动上传 | 日常 |
| **B. 全自动** | 工作流调 Claude API 写 | ✅ | ✅ Playwright 发布 | 无人值守 |

**用法 A 流程**：把视频丢进 `input/` → 告诉 Claude 链接 + 平台 → Claude 用 WebFetch 看链接、按各平台要求写好 `content.json` → 跑 `run --content content.json --no-publish` → 去 `output/` 拿 `content.md` + `covers/` 手动上传。
最小依赖：`pip install Pillow imageio-ffmpeg PyYAML`（不用装 anthropic / playwright）。

**用法 B 流程**：`export ANTHROPIC_API_KEY` + 各平台 `login` 一次 → `run --link <链接> --platforms ...` → 自动写文案、出封面、浏览器发布（默认停在发布按钮前）。

## 五、模块详解

```
src/autopromo/
├── cli.py            命令行入口：run / login / platforms / template
├── config.py         读取 config.yaml，带默认值
├── platforms.py      ★ 平台注册表：各平台封面风格/文案口吻/是否标转载（单一事实来源）
├── pipeline.py       主流水线：识别视频→拿文案→出封面→组装待发布包→落地产物
├── models.py         数据模型（dataclass）
├── content/
│   ├── source.py     抓取文案来源链接（requests + BeautifulSoup，6000 字截断）
│   ├── generator.py  调 Claude 写各平台文案（Opus 4.8 + adaptive thinking）
│   └── spec.py       读取"已写好的文案 JSON" + 生成带各平台要求的模板
├── cover/
│   ├── frames.py     从视频抽最清晰一帧（imageio-ffmpeg，无需系统 ffmpeg）
│   ├── render.py     Pillow 渲染封面（自适应遮罩、标题自动缩放、两种布局）
│   └── builder.py    出"各平台专属 + 三张通用"封面（抽一次帧、复用底图）
└── publish/
    ├── browser.py    Playwright 持久化上下文（复用登录态）
    ├── flow.py       声明式上传流程 + 通用执行器
    ├── flows.py      ★ 各平台上传页 URL + 候选选择器（平台改版改这里）
    └── publisher.py  发布编排 + 登录辅助
```

### platforms.py —— 整套个性化的"单一事实来源"

每个平台一份 `PlatformProfile`，定义三类信息，**两头都用**（写文案进 prompt、出封面进渲染器）：

- **封面风格** `CoverStyle`：强调色、标题色、角标文案、底部遮罩强度、布局（`bottom` 压底 / `card` 笔记卡片）。
- **文案口吻** `copy_style` + 标题字数上限 `title_max` + 话题标签风格 `hashtag_hint`。
- **平台规则** `mark_repost`（B 站 = True，如实标转载）。

已注册：`douyin`(抖音/3:4) `xiaohongshu`(小红书/3:4/笔记卡片) `shipinhao`(视频号/3:4) `xigua`(西瓜/16:9) `toutiao`(头条/16:9) `bilibili`(B站/16:9/标转载)。

> **加平台 / 改风格 / 改口吻 = 只改这一个文件。**

### content/ —— 文案

- **source.py**：`requests` 抓网页 → `BeautifulSoup` 去掉 script/nav/footer 噪声 → 提取标题（含 og:title）+ 正文纯文本，截断到 ~6000 字。**抓失败不致命**（`fetched_ok=False`），退化到"基于视频名 + 人设"立意。
- **generator.py**（用法 B）：把人设 + 来源资料 + 视频名 + **各平台要求**拼成 prompt，**一次调用** Claude（`claude-opus-4-8`，`thinking: adaptive`，`effort` 可配，streaming + `get_final_message` 防超时）返回一个 JSON：一套封面文案 + 每平台（标题/正文/标签）。一次产出所有平台，**省 token**。`import anthropic` 改为**函数内惰性导入**——只用用法 A 时无需安装该包。
- **spec.py**（用法 A）：`load_spec()` 读取我亲手写的文案 JSON（校验平台齐全、标题/正文非空）；`write_template()` 生成带 `_guidance`（各平台口吻/字数/标签/是否标转载）的空模板，照着填。

文案 JSON 结构：
```json
{
  "cover":     {"title": "...", "english": "...", "chinese": "..."},
  "platforms": {
    "douyin": {"title": "...", "body": "...", "hashtags": ["...", "..."]}
  }
}
```

### cover/ —— 封面（见下一节细讲）

### publish/ —— 发布

- **browser.py**：`launch_persistent_context(user_data_dir=...)`，用持久化用户数据目录**复用登录态**。首次 `login <平台>` 手动扫码一次，cookie 存进 profile，之后自动复用。
- **flow.py**：`UploadFlow` dataclass（每个字段是一组**候选选择器**）+ 通用执行器 `execute_flow`：`打开上传页 → 传视频 → 等转码 → 填标题/简介 → 传封面 →（必要时）标转载 →（可选）发布`。每步自动截图到 `debug/` 便于排查。`auto_submit=False` 时停在发布按钮前。
- **flows.py**：各平台的 `UploadFlow` 实例 + 登录页 URL。选择器写成候选列表，平台改版时多半只需补一个新选择器。
- **publisher.py**：`publish_packages()` 在一个浏览器会话里逐平台执行（单平台失败不影响其它）；`open_login()` 供首次登录。

### pipeline.py / cli.py / config.py

- **pipeline.py**：`find_video()`（取最新 mtime）、`produce()`（按 `content_spec` 决定走 A 还是 B）、`_write_outputs()`（生成 `content.json` + "照着发"的 `content.md`：每平台标注用哪张封面、标题/正文放代码块可一键复制、B 站提示标转载）。
- **cli.py**：子命令 `run`（`--link` / `--content` / `--platforms` / `--video` / `--no-publish` / `--keep-open`）、`login <平台>`、`platforms`、`template`。
- **config.py**：读 `config.yaml`；`auto_submit` **全局开关与单平台开关取"与"**——两者都为 true 才真发，双保险防误发。API Key 只从环境变量读，不进配置文件。

## 六、封面渲染的实现细节

封面是这套工具里**技术含量最高、也最经得起打磨**的部分。

### 抽帧（frames.py）

- 用 `imageio-ffmpeg` **自带的 ffmpeg 二进制**，无需系统安装 ffmpeg。
- 先解析时长（跑一遍 ffmpeg 读 stderr 的 `Duration`），在 **10%~85%** 之间均匀采样 5 帧，跳过片头片尾。
- 每帧算**清晰度**（缩小后取边缘强度方差，`FIND_EDGES`），**挑最清晰的一帧**，避开黑场/转场糊帧。
- 抽帧失败 → 返回 `None`，渲染端退化为**渐变兜底底图**，不中断。

### 渲染（render.py）

输出尺寸：`16:9→1920×1080`、`4:3→1440×1080`、`3:4→1080×1440`。底图等比缩放后**居中裁剪**（cover 行为）到目标尺寸。

两种布局：
- **bottom（压底）**：底部黑色渐变遮罩 + 标题压底 + 双语钩子（抖音/视频号/西瓜/头条/B站）。
- **card（笔记卡片）**：顶部白色卡片写标题（小红书笔记风），底图在下半。

三个打磨点（让任意画面都清晰、不溢出）：
1. **标题自动缩放** `_fit_title`：从设定字号往下试，直到折行 ≤3 行；放不下就缩字号（有下限），**长标题不被截断、不溢出画面**。
2. **自适应遮罩** `_region_luminance`：测底图**底部区域平均亮度**，亮画面（如高饱和画面）自动**加重压字遮罩**，保证文字始终压得住。
3. **中英混排折行** `_wrap`：中文逐字、英文整词，两者兼顾，不会把英文单词从中间切断。

文字加**描边**（stroke）增强对比；徽章用平台强调色圆角色块；双语钩子前加一段强调色竖条。

> 注：中文字体用文泉驿正黑（容器自带），不含彩色 emoji 字形，所以平台**角标徽章用纯文字**（去掉 emoji 豆腐块）；正文里的 emoji 由平台自己渲染、不进封面。

### 构建（builder.py）

`build_covers()`：**抽一次帧、复用底图**，渲染：
- 每个目标平台一张**专属比例 + 专属风格**封面（做到"每个平台封面不一样"）。
- 三张**通用封面**（16:9 / 4:3 / 3:4，中性风格），覆盖横版/通用/竖版平台。

## 七、关键设计决策与权衡

| 决策 | 选择 | 理由 / 权衡 |
|---|---|---|
| 触发方式 | 命令驱动，不监听文件夹 | 用户明确要"发指令再做"，更可控；省掉文件监听的复杂度。 |
| 技术栈 | Python | 视频处理(ffmpeg)、Pillow 出图、Playwright 自动化、Claude SDK 生态最顺。 |
| 封面生成 | 模板叠字（Pillow），非 AI 生图 | 文字可控不糊、免费、可按平台风格精确控制；英语学习封面文字密集，模板更稳。 |
| 平台差异 | 集中到 `platforms.py` | 单一事实来源，改一处即可；避免散落各处难维护。 |
| 文案生成 | 一次 API 调用产出所有平台 | 省 token；一致的封面文案 + 各平台定制正文。 |
| 发布登录 | 持久化 profile 复用 cookie | 对上"我会把浏览器登录好"；不存账号密码，只复用浏览器登录态。 |
| 发布流程 | 声明式候选选择器 + 通用执行器 | 平台前端常改版，候选列表 + 集中配置，改版只补选择器。 |
| 发布安全 | 默认 `auto_submit=False`，双开关 | 防误发；先人工确认跑顺，再逐平台打开自动发布。 |
| 文案来源 | A 路径"我写" / B 路径"调 API" | 用户在 App 里运行 → 文案由 Claude 直接写，无需 Key/外网；保留 B 给无人值守。 |
| 依赖 | anthropic / playwright 可选 | 惰性导入 + 最小依赖，用法 A 极简上手。 |
| 抓链接失败 | 优雅降级 | 链接 403/超时不中断，退化到基于视频名+人设。 |

## 八、搭建过程（时间线）

1. **探测环境**：确认 Python 3.11、Pillow 可用、自带中文字体；发现系统无 ffmpeg → 决定用 `imageio-ffmpeg` 兜底。
2. **对齐需求**：跟用户确认四点 —— 每平台封面各不同、用已登录浏览器发布、命令驱动（不监听）、技术栈用 Python。
3. **搭骨架**：`.gitignore` / `requirements` / `config.example.yaml` / 包结构 / `models.py`。
4. **平台注册表** `platforms.py`：把各平台封面风格、文案口吻、是否标转载定义清楚。
5. **content/**：`source.py` 抓链接、`generator.py` 调 Claude（查证模型 ID = `claude-opus-4-8`、adaptive thinking）。
6. **cover/**：`frames.py` 抽帧、`render.py` 渲染、`builder.py` 构建 —— **当场渲染测试并肉眼检查成图**，发现 emoji 豆腐块 → 角标改纯文字。
7. **publish/**：`browser.py` 持久化登录、`flow.py` 通用执行器、`flows.py` 各平台选择器、`publisher.py` 编排。
8. **pipeline.py / cli.py**：串起来 + 命令行。
9. **冒烟测试**：装非 playwright 依赖、stub 掉真实 API，跑通 `produce` 全链路、全模块导入。
10. **真视频验证**：用自带 ffmpeg 造真视频，**真实抽帧 → 真实渲染封面**，肉眼确认。
11. **content.md 升级**：改成"每平台用哪张封面 + 标题 + 简介"的照着发清单（服务手动上传）。
12. **新增 content-spec 路径**：`spec.py` + `--content` + `template` 子命令 + anthropic 惰性导入 —— 支持"App 里我写文案、不调 API"。
13. **封面打磨**：标题自动缩放 + 按底图亮度自适应遮罩，并验证超长标题/亮底图两个边界。

## 九、验证记录

在沙箱里**真实跑通**（用自带 ffmpeg 造的真视频）：

- ✅ 识别 input 最新视频
- ✅ 视频抽帧（探测 8s、抽 1280×720 最清晰帧）
- ✅ 各平台专属封面 + 三张通用封面（6 张，叠真实帧）
- ✅ `template` 出模板 → 填文案 → `run --content` 出封面 + 清单（离线、无 Key）
- ✅ `content.md` 照着发清单（B 站自动提示标转载）
- ✅ 不装 `anthropic` 也能跑用法 A（遮蔽其导入仍正常）
- ✅ 边界：超长标题(33字)自动缩字号、3 行内不截断
- ✅ 边界：亮底图自适应加重遮罩、文字清晰

**未在沙箱实跑**（纯因沙箱无外网 + 无 API Key，逻辑就绪，用户本机/App 可用）：
- ⏳ 抓取外部链接（沙箱出不去网）
- ⏳ 调 Claude API 写文案（无 Key；用法 A 根本不需要）
- ⏳ 浏览器自动发布（无登录态浏览器；且按用户选择暂缓，改手动上传）

## 十、已知限制

1. **发布选择器会过时**：`publish/flows.py` 的选择器是合理初值，**未在真站点实测**。各平台创作中心前端改版频繁，首次实跑需配合 `--keep-open` 和 `debug/` 截图微调。
2. **风控**：自动化上传可能触发验证码/风控，`headless:false` + `slow_mo` 更稳。
3. **实时热点不可知**：模型无外网、知识有截止日期，**无法获取"当天热点"tag**；实战中靠抖音发布页自带的话题推荐，或用户告知当天热点。
4. **字幕未落地**：封面英文钩子目前是据链接/主题写的，尚未读取视频同名 `.srt` 取视频里真实出现的句子。
5. **emoji**：封面字体不含彩色 emoji，角标已改纯文字。
6. **B 站转载流程偏简**：当前只点"转载"，实际还需选单选项 + 填来源链接。
